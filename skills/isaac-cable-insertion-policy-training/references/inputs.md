## Inputs and boundaries

- Use the standalone package in [NVIDIA-ISAAC-ROS/isaac_ros_manipulation](https://github.com/NVIDIA-ISAAC-ROS/isaac_ros_manipulation/tree/release-r1), default ref `release-r1`. It is public; clone over HTTPS without requiring GitHub authentication.
- Resolve `training_root` to the absolute `isaaclab_training/` package directory. [Setup](setup.md) covers user-selected paths, reuse, and fresh installation.
- Use the training project’s pinned Isaac Lab wheel-builder dependency. A source IsaacLab checkout or its `.venv` is not a standalone training root; follow [Setup](setup.md) to select a compatible package.
- Keep the training project's source, `pyproject.toml`, `uv.lock`, and package metadata unchanged. Apply the default release's skill-managed supplements and CPU ONNX installation exclusion as described in Setup; fixes belong in the skill and `.venv`, not the upstream project.
- Default to `IsaacTraining-DisplayPortInsertion-Rizon4s-TaskSpace-ROS-Inference`, 256 environments, 128 steps per rollout, 1000 updates, and three runs. The release’s task-space curriculum anneals over 333 updates. Joint-space defaults remain 512 steps, 1500 updates, and a 500-update anneal. Confirm the selected ref’s task/agent configuration before launching; record any intentional departure. The supervisor records the effective anneal in the plan and passes it explicitly to training.
- Recurrent PPO uses 16 mini-batches: use a positive multiple of 16 environments, or explicitly adjust and record the mini-batch count for a smaller smoke test. Never silently cap reset IK or change contact physics to speed setup.
- Honor the time budget. Short runs need explicit rollout/curriculum choices and are not evidence of a fully trained policy.
- Use the official [setup guide](https://nvidia-isaac-ros.github.io/manipulation/training/setup_training.html) and [DisplayPort guide](https://nvidia-isaac-ros.github.io/manipulation/training/tasks/displayport_insertion.html). Read the selected repository’s `pyproject.toml`, `uv.lock`, and task configuration too. The installed revision is authoritative when development docs differ. If the browser cannot reach the public docs, try the authorized workstation network; use the selected repository files when docs remain unavailable.
- For video, explicitly select a Kit capture source with `HEADLESS=1 --viz kit --video`. The docs’ `--viz none --video` example is not a substitute for passing the video smoke test in the selected environment.
- This is simulation training. Do not deploy checkpoints to hardware or claim hardware readiness from simulation metrics. A separate deployment skill may have its own environment requirements; do not make training depend on them.
